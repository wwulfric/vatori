# Flow IPC Protocol v1

Flow IPC Protocol v1 is the first runtime protocol for moving Vaadin Desktop beyond localhost HTTP compatibility mode.

Current implementation status: **minimum runtime slice implemented with UIDL writer, visible Flow client engine ownership for bootstrap, click-event patches, one server push and one verification resync, IPC-backed Flow client XHR dispatch, and real Flow client resource loading/init**. It supports a local WebView shell, Java sidecar stdin/stdout transport, bootstrap, event, replace-root patch, desktop command/capabilityResult, push, resync, resource request/response and shutdown. The runtime generates bootstrap and push UIDL with `UidlWriter`; bootstrap UIDL carries Flow's `Vaadin-Security-Key`; the WebView imports `FlowBootstrap.js` and an augmented `FlowClient.js`, promotes the registered Flow client container to the visible surface, installs an `XMLHttpRequest` shim for the Flow client engine and sends the real Flow client click/resync UIDL RPC over IPC with CSRF/security key, `syncId`, `clientId` and Flow node id. Java dispatches those bodies through `UidlRequestHandler`/`ServerRpcHandler` to produce UIDL patches consumed by the visible Flow client. The repository-local UIDL applier remains as a diagnostic fallback for non-engine or failed-delivery paths.

## Prefixes

Swift host trace:

```text
HOST_PROTOCOL {"direction":"recv","type":"launch",...}
```

Flow IPC envelopes between WebView/host and Java sidecar:

```text
VFIPC1 {"version":"flow-ipc-v1","type":"bootstrapRequest",...}
```

Compatibility-mode desktop capability command envelopes from Java to host:

```text
VDP1 {"type":"command","id":"desktop-command-1",...}
```

In `dev-ipc`, desktop capability commands also use `VFIPC1` Flow IPC envelopes:

```text
VFIPC1 {"version":"flow-ipc-v1","type":"command","id":"desktop-command-1",...}
```

## Envelope

```json
{
  "version": "flow-ipc-v1",
  "type": "event",
  "id": "webview-3",
  "correlationId": "webview-3",
  "sessionId": "flow-ipc-session",
  "uiId": "main",
  "route": "",
  "payload": {
    "dispatch": "flow-client-xhr",
    "componentId": "ipc-button",
    "nodeId": 16,
    "securityKey": "trace-csrf",
    "event": "uidl-rpc",
    "uidlRpc": {
      "csrfToken": "trace-csrf",
      "rpc": [
        {
          "type": "event",
          "node": 16,
          "event": "click",
          "data": {}
        }
      ],
      "syncId": -1,
      "clientId": 1
    }
  },
  "error": null,
  "timestamp": 1778997000000
}
```

Fields:

- `version`: protocol version, currently `flow-ipc-v1`.
- `type`: message type.
- `id`: message id.
- `correlationId`: request/response correlation id.
- `sessionId`: desktop Flow session id.
- `uiId`: desktop UI/window id.
- `route`: Flow route.
- `payload`: message payload.
- `error`: structured error or `null`.
- `timestamp`: sender timestamp in epoch milliseconds.

## Current Patch Payload

The current patch payload has two parts:

- `uidl`: real Vaadin server-side UIDL generated by `UidlWriter` for bootstrap or `UidlRequestHandler` for event patches.
- `tree`: repository-local render tree retained as a diagnostic fallback while the visible Flow client engine consumes bootstrap, click-event, push and verification resync UIDL.

```json
{
  "patchType": "replaceRoot",
  "reason": "event",
  "transport": "flow-ipc",
  "compatibilityMode": false,
  "uidl": {
    "source": "UidlRequestHandler",
    "format": "vaadin-uidl-json",
    "containsChanges": true,
    "containsSyncId": true,
    "consumedByWebView": true,
    "consumer": "flow-client-engine-visible",
    "body": "{\"clientId\":0,\"changes\":[{\"node\":13,\"type\":\"put\",\"key\":\"text\",\"feat\":7,\"value\":\"Clicks: 1\"}],\"syncId\":-1}"
  },
  "tree": {
    "id": "ipc-root",
    "tag": "vaadin-vertical-layout",
    "kind": "layout",
    "text": "",
    "clickable": false,
    "children": []
  }
}
```

The UIDL is real server-side Flow output. Bootstrap, click-event patches, one server push and one verification resync are consumed by the visible Flow client engine after the WebView imports `FlowBootstrap.js` / `FlowClient.js` and promotes the registered client container to `#flow-client-engine-root`. The local render tree remains for diagnostics and failed-delivery fallback.

## Current Bootstrap Security Key

Vaadin Flow's browser bootstrap normally adds `ApplicationConstants.UIDL_SECURITY_TOKEN_ID`, serialized as `Vaadin-Security-Key`, after `UidlWriter.createUidl(...)`. The IPC runtime now mirrors that bootstrap step in `DesktopFlowRuntimeSession.createBootstrapUidl()`.

The WebView bridge reads the key from `clientState.securityKey` and from the bootstrap UIDL body, then sends it back on event and resync envelopes. The UIDL RPC body still uses Flow's regular `csrfToken` field because that is what `ServerRpcHandler` validates. In the current bridge, `securityKey` and `csrfToken` are the same UI token.

## Current Resource Payload

`dev-ipc` now exposes a minimum Flow client resource channel. `bootstrapResponse` includes a `flowClientResources` manifest built from the Java sidecar classpath:

```json
{
  "flowClientResources": {
    "source": "flow-client-classpath",
    "transport": "flow-ipc",
    "resourceLoading": "ipc-resource-request",
    "resources": [
      {
        "path": "META-INF/frontend/FlowBootstrap.js",
        "kind": "flow-bootstrap-module",
        "bytes": 7623,
        "sha256": "..."
      }
    ]
  }
}
```

The WebView bridge currently requests `FlowBootstrap.js` and then `FlowClient.js` as a resource probe:

```json
{
  "type": "resourceRequest",
  "payload": {
    "purpose": "flow-client-resource-probe",
    "path": "META-INF/frontend/FlowBootstrap.js",
    "expectedSha256": "...",
    "securityKey": "trace-csrf"
  }
}
```

Java checks the envelope `sessionId`/`uiId` and `securityKey`, then returns:

```json
{
  "type": "resourceResponse",
  "payload": {
    "flowClientResource": true,
    "available": true,
    "path": "META-INF/frontend/FlowBootstrap.js",
    "kind": "flow-bootstrap-module",
    "encoding": "utf-8",
    "body": "..."
  }
}
```

This proves no-HTTP resource delivery for the first real Flow client assets. The WebView verifies that the bootstrap body contains `window.Vaadin.Flow.initApplication` and `export { init }`, imports it as a Blob-backed ES module, checks that the module exports `init`, and calls `FlowBootstrap.init` with an IPC bootstrap config. It then imports the augmented `FlowClient.js`, calls `FlowClient.init`, verifies that the GWT client registers a Flow client object, checks bootstrap UIDL node bindings through `client.getByNodeId(...)`, verifies the IPC message/resync bridge methods, installs an IPC-backed XHR bridge and promotes the registered Flow client container to the visible renderer.

## Current Push Payload

`dev-ipc` emits one server-initiated `push` after bootstrap. The Java runtime mutates the server-side Flow component tree, serializes the async delta with `UidlWriter`, and the WebView delivers the UIDL body into the visible Flow client engine through the IPC message bridge.

```json
{
  "type": "push",
  "payload": {
    "reason": "server-initiated-update",
    "transport": "flow-ipc",
    "compatibilityMode": false,
    "uidlWriter": true,
    "uidl": {
      "source": "UidlWriter",
      "reason": "push",
      "async": true,
      "consumedByWebView": true,
      "consumer": "flow-client-engine-visible"
    }
  }
}
```

## Current Event Payload

`dev-ipc` no longer sends only `{action, componentId}`. The verified path calls the real Flow client engine. Its XHR request is intercepted by the Swift WebView bridge and forwarded as a Flow-client-shaped UIDL RPC object:

```json
{
  "type": "event",
  "payload": {
    "dispatch": "flow-client-xhr",
    "componentId": "ipc-button",
    "nodeId": 16,
    "securityKey": "trace-csrf",
    "event": "uidl-rpc",
    "uidlRpc": {
      "csrfToken": "trace-csrf",
      "rpc": [
        {
          "type": "event",
          "node": 16,
          "event": "click",
          "data": {}
        }
      ],
      "syncId": -1,
      "clientId": 1
    }
  }
}
```

The Java side still retains a legacy translator for the old simplified event payload as a fallback, but the verified path is `dispatch=flow-client-xhr`. The first Flow client XHR message may be `attachExistingElementById` with `clientId=0`; the desktop runtime acknowledges it and advances Vaadin's internal client-to-server message id before the actual click RPC arrives with `clientId=1`.

The Java runtime checks the outer envelope `sessionId` and `uiId` before event dispatch. A mismatch is rejected as `invalidClientState` before the UIDL RPC body reaches `UidlRequestHandler`.

## Current Resync Payload

When `VAADIN_DESKTOP_FLOW_IPC_AUTO_RESYNC=1` is set for verification, the visible Flow client engine creates one resync XHR after the event patch. The Swift bridge forwards that Flow-client-shaped body as a `resync` envelope. Java responds with a normal `patch` envelope whose UIDL payload is generated through `UidlRequestHandler` with `resync=true`, and the Swift bridge completes the pending Flow client XHR with that UIDL response.

```json
{
  "type": "resync",
  "payload": {
    "dispatch": "flow-client-xhr",
    "reason": "verification-resync-after-event",
    "securityKey": "trace-csrf",
    "event": "uidl-resync",
    "uidlRpc": {
      "csrfToken": "trace-csrf",
      "resynchronize": true,
      "rpc": [],
      "syncId": -1,
      "clientId": 3
    },
    "syncId": -1,
    "clientId": 3
  }
}
```

## Current Command Payload

Desktop API calls in `dev-ipc` use the same envelope with `type=command`:

```json
{
  "type": "command",
  "id": "desktop-command-3",
  "correlationId": "desktop-command-3",
  "payload": {
    "command": "clipboard.writeText",
    "args": {
      "text": "Vaadin Flow over IPC clicks: 1"
    }
  }
}
```

The Swift host responds with `type=capabilityResult`:

```json
{
  "type": "capabilityResult",
  "id": "capability-desktop-command-3",
  "correlationId": "desktop-command-3",
  "payload": {
    "success": true,
    "command": "clipboard.writeText",
    "mode": "native-nspasteboard",
    "permissionMode": "allow-all-dev",
    "permissionDecision": "allowed",
    "permissionReason": "development-default",
    "permissionScope": "window:main"
  }
}
```

Implemented host commands in `dev-ipc`:

- `window.setTitle`: updates the AppKit `NSWindow` title.
- `clipboard.writeText`: writes to macOS `NSPasteboard`.
- `notification.show`: accepted as trace-only scaffold.

The v1 capability permission model is deliberately minimal. `dev-ipc` is `permissionMode=allow-all-dev`: known commands are allowed for the main window and every result carries a permission decision for trace review. Unknown commands are denied as `unsupported-command`. The next production model should replace this with a manifest-gated policy keyed by window, origin and capability.

## Error Model

Errors use the same envelope with `type=error` and an `error` object:

```json
{
  "type": "error",
  "id": "webview-5",
  "sessionId": "flow-ipc-session",
  "uiId": "main",
  "payload": {
    "reason": "verification-error-probe"
  },
  "error": {
    "code": "webviewVerificationProbe",
    "message": "Verification error probe from WebView bridge"
  }
}
```

`invalidCsrfToken` is emitted when a WebView `event` envelope carries a security key or UIDL RPC body whose `csrfToken` does not match the desktop `UI` token. `invalidClientState` is emitted for malformed or stale envelope/UIDL RPC metadata such as mismatched `sessionId`/`uiId`, missing/mismatched `syncId` or out-of-order `clientId`. The runtime rejects those messages before they reach `UidlRequestHandler`. The WebView bridge can also originate `type=error` envelopes; the verification hook uses `webviewVerificationProbe` so the trace contains a client-side error-reporting example without breaking the normal app path.

## Compatibility Strategy

- `dev` and `dev-swift` remain compatibility HTTP modes.
- `dev-ipc` uses Flow IPC Protocol v1 and must log `transport=flow-ipc` and `compatibilityMode=false`.
- Full push queue/reconnect semantics, upload/download and full push/WebSocket replacement remain future work. The current resource loading slice serves, imports and initializes `FlowBootstrap.js` / augmented `FlowClient.js` over IPC, verifies bootstrap UIDL binding and makes the registered GWT client the visible UIDL renderer for bootstrap, click-event, push and verification resync patches.
