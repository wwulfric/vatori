# Flow IPC Protocol v1

Flow IPC Protocol v1 is the first runtime protocol for moving Vaadin Desktop beyond localhost HTTP compatibility mode.

Current implementation status: **minimum runtime slice implemented with UIDL writer, WebView-produced UIDL RPC dispatch, minimum UIDL patch consumption, one server-initiated UIDL push, one verification resync and one Flow client resource loading/init probe**. It supports a local WebView shell, Java sidecar stdin/stdout transport, bootstrap, event, replace-root patch, desktop command/capabilityResult, push, resync, resource request/response and shutdown. The runtime generates bootstrap and push UIDL with `UidlWriter`; bootstrap UIDL now carries Flow's `Vaadin-Security-Key`; verification resync receives Vaadin's `resynchronize=true` signal from `UidlWriter`; the WebView bridge sends click events as UIDL RPC bodies with CSRF/security key, `syncId`, `clientId` and Flow node id; Java dispatches them through `UidlRequestHandler`/`ServerRpcHandler` to produce event UIDL patches. Bootstrap advertises real Vaadin `flow-client` classpath resources and the WebView loads and initializes `FlowBootstrap.js` / `FlowClient.js` through IPC. The WebView applies bootstrap/push/event UIDL `changes` through a minimum applier and treats resync as a rebuild boundary, so this is closer to Flow client behavior but still not full Flow client engine parity.

## Prefixes

Swift host trace:

```text
HOST_PROTOCOL {"direction":"recv","type":"launch",...}
```

Flow IPC envelopes between WebView/host and Java sidecar:

```text
VFIPC1 {"version":"flow-ipc-v1","type":"bootstrapRequest",...}
```

Compatibility-mode desktop capability command envelopes from Java to host:

```text
VDP1 {"type":"command","id":"desktop-command-1",...}
```

In `dev-ipc`, desktop capability commands also use `VFIPC1` Flow IPC envelopes:

```text
VFIPC1 {"version":"flow-ipc-v1","type":"command","id":"desktop-command-1",...}
```

## Envelope

```json
{
  "version": "flow-ipc-v1",
  "type": "event",
  "id": "webview-2",
  "correlationId": "webview-2",
  "sessionId": "flow-ipc-session",
  "uiId": "main",
  "route": "",
  "payload": {
    "dispatch": "flow-client-rpc",
    "componentId": "ipc-button",
    "nodeId": 16,
    "securityKey": "trace-csrf",
    "event": "click",
    "uidlRpc": {
      "csrfToken": "trace-csrf",
      "securityKey": "trace-csrf",
      "rpc": [
        {
          "type": "event",
          "node": 16,
          "event": "click",
          "data": {}
        }
      ],
      "syncId": -1,
      "clientId": 0
    }
  },
  "error": null,
  "timestamp": 1778997000000
}
```

Fields:

- `version`: protocol version, currently `flow-ipc-v1`.
- `type`: message type.
- `id`: message id.
- `correlationId`: request/response correlation id.
- `sessionId`: desktop Flow session id.
- `uiId`: desktop UI/window id.
- `route`: Flow route.
- `payload`: message payload.
- `error`: structured error or `null`.
- `timestamp`: sender timestamp in epoch milliseconds.

## Current Patch Payload

The current patch payload has two parts:

- `uidl`: real Vaadin server-side UIDL generated by `UidlWriter` for bootstrap or `UidlRequestHandler` for event patches.
- `tree`: repository-local render tree retained as fallback while the current WebView shell consumes the supported UIDL `changes` subset.

```json
{
  "patchType": "replaceRoot",
  "reason": "event",
  "transport": "flow-ipc",
  "compatibilityMode": false,
  "uidl": {
    "source": "UidlRequestHandler",
    "format": "vaadin-uidl-json",
    "containsChanges": true,
    "containsSyncId": true,
    "consumedByWebView": true,
    "consumer": "minimum-webview-uidl-applier",
    "body": "{\"clientId\":0,\"changes\":[{\"node\":13,\"type\":\"put\",\"key\":\"text\",\"feat\":7,\"value\":\"Clicks: 1\"}],\"syncId\":-1}"
  },
  "tree": {
    "id": "ipc-root",
    "tag": "vaadin-vertical-layout",
    "kind": "layout",
    "text": "",
    "clickable": false,
    "children": []
  }
}
```

The UIDL is real server-side Flow output. Bootstrap, push and event patches are consumed by the minimum WebView UIDL changes applier, so `consumedByWebView=true` is expected for `UidlWriter` bootstrap/push and `UidlRequestHandler` event patches. Resync uses Vaadin's real `resynchronize=true` signal and rebuilds from the local tree fallback until the full Flow client engine bridge replaces this behavior.

## Current Bootstrap Security Key

Vaadin Flow's browser bootstrap normally adds `ApplicationConstants.UIDL_SECURITY_TOKEN_ID`, serialized as `Vaadin-Security-Key`, after `UidlWriter.createUidl(...)`. The IPC runtime now mirrors that bootstrap step in `DesktopFlowRuntimeSession.createBootstrapUidl()`.

The WebView bridge reads the key from `clientState.securityKey` and from the bootstrap UIDL body, then sends it back on event and resync envelopes. The UIDL RPC body still uses Flow's regular `csrfToken` field because that is what `ServerRpcHandler` validates. In the current bridge, `securityKey` and `csrfToken` are the same UI token.

## Current Resource Payload

`dev-ipc` now exposes a minimum Flow client resource channel. `bootstrapResponse` includes a `flowClientResources` manifest built from the Java sidecar classpath:

```json
{
  "flowClientResources": {
    "source": "flow-client-classpath",
    "transport": "flow-ipc",
    "resourceLoading": "ipc-resource-request",
    "resources": [
      {
        "path": "META-INF/frontend/FlowBootstrap.js",
        "kind": "flow-bootstrap-module",
        "bytes": 7623,
        "sha256": "..."
      }
    ]
  }
}
```

The WebView bridge currently requests `FlowBootstrap.js` and then `FlowClient.js` as a resource probe:

```json
{
  "type": "resourceRequest",
  "payload": {
    "purpose": "flow-client-resource-probe",
    "path": "META-INF/frontend/FlowBootstrap.js",
    "expectedSha256": "...",
    "securityKey": "trace-csrf"
  }
}
```

Java checks the envelope `sessionId`/`uiId` and `securityKey`, then returns:

```json
{
  "type": "resourceResponse",
  "payload": {
    "flowClientResource": true,
    "available": true,
    "path": "META-INF/frontend/FlowBootstrap.js",
    "kind": "flow-bootstrap-module",
    "encoding": "utf-8",
    "body": "..."
  }
}
```

This proves no-HTTP resource delivery for the first real Flow client assets. The WebView verifies that the bootstrap body contains `window.Vaadin.Flow.initApplication` and `export { init }`, imports it as a Blob-backed ES module, checks that the module exports `init`, and calls `FlowBootstrap.init` with an IPC bootstrap config. It then imports `FlowClient.js`, calls `FlowClient.init` and verifies that the GWT client registers a Flow client object. UIDL patches are still applied by the repository-local applier rather than being routed through that registered client.

## Current Push Payload

`dev-ipc` emits one server-initiated `push` after bootstrap. The Java runtime mutates the server-side Flow component tree, serializes the delta with `UidlWriter`, and the WebView applies the same UIDL changes path used for event patches.

```json
{
  "type": "push",
  "payload": {
    "reason": "server-initiated-update",
    "transport": "flow-ipc",
    "compatibilityMode": false,
    "uidlWriter": true,
    "uidl": {
      "source": "UidlWriter",
      "reason": "push",
      "consumedByWebView": true,
      "consumer": "minimum-webview-uidl-applier"
    }
  }
}
```

## Current Event Payload

`dev-ipc` no longer sends only `{action, componentId}`. The WebView bridge now sends a Flow-client-shaped UIDL RPC object:

```json
{
  "type": "event",
  "payload": {
    "dispatch": "flow-client-rpc",
    "componentId": "ipc-button",
    "nodeId": 16,
    "securityKey": "trace-csrf",
    "event": "click",
    "uidlRpc": {
      "csrfToken": "trace-csrf",
      "securityKey": "trace-csrf",
      "rpc": [
        {
          "type": "event",
          "node": 16,
          "event": "click",
          "data": {}
        }
      ],
      "syncId": -1,
      "clientId": 0
    }
  }
}
```

The Java side still retains a legacy translator for the old simplified event payload as a fallback, but the verified path is `dispatch=flow-client-rpc`.

The Java runtime checks the outer envelope `sessionId` and `uiId` before event dispatch. A mismatch is rejected as `invalidClientState` before the UIDL RPC body reaches `UidlRequestHandler`.

## Current Resync Payload

When `VAADIN_DESKTOP_FLOW_IPC_AUTO_RESYNC=1` is set for verification, the WebView bridge sends one `resync` envelope after the event patch. Java responds with a normal `patch` envelope whose UIDL payload is generated by `UidlWriter` with `resync=true`. Vaadin currently emits a `resynchronize=true` signal instead of a full `changes` list, so the WebView treats that payload as a rebuild boundary and uses the repository-local tree fallback.

```json
{
  "type": "resync",
  "payload": {
    "reason": "verification-resync-after-event",
    "securityKey": "trace-csrf",
    "syncId": -1,
    "clientId": 1
  }
}
```

## Current Command Payload

Desktop API calls in `dev-ipc` use the same envelope with `type=command`:

```json
{
  "type": "command",
  "id": "desktop-command-3",
  "correlationId": "desktop-command-3",
  "payload": {
    "command": "clipboard.writeText",
    "args": {
      "text": "Vaadin Flow over IPC clicks: 1"
    }
  }
}
```

The Swift host responds with `type=capabilityResult`:

```json
{
  "type": "capabilityResult",
  "id": "capability-desktop-command-3",
  "correlationId": "desktop-command-3",
  "payload": {
    "success": true,
    "command": "clipboard.writeText",
    "mode": "native-nspasteboard"
  }
}
```

Implemented host commands in `dev-ipc`:

- `window.setTitle`: updates the AppKit `NSWindow` title.
- `clipboard.writeText`: writes to macOS `NSPasteboard`.
- `notification.show`: accepted as trace-only scaffold.

## Error Model

Errors use the same envelope with `type=error` and an `error` object:

```json
{
  "type": "error",
  "error": {
    "code": "unsupportedEvent",
    "message": "Only click events are supported by the v1 minimum adapter."
  }
}
```

`invalidCsrfToken` is emitted when a WebView `event` envelope carries a security key or UIDL RPC body whose `csrfToken` does not match the desktop `UI` token. `invalidClientState` is emitted for malformed or stale envelope/UIDL RPC metadata such as mismatched `sessionId`/`uiId`, missing/mismatched `syncId` or out-of-order `clientId`. The runtime rejects those messages before they reach `UidlRequestHandler`.

## Compatibility Strategy

- `dev` and `dev-swift` remain compatibility HTTP modes.
- `dev-ipc` uses Flow IPC Protocol v1 and must log `transport=flow-ipc` and `compatibilityMode=false`.
- Full Flow client UIDL consumption, upload/download and full push/WebSocket replacement remain future work. The current resource loading slice serves, imports and initializes `FlowBootstrap.js` / `FlowClient.js` over IPC but does not yet make the registered GWT client the visible UIDL renderer.

```bash
bash bin/flow-ipc-trace-inspect --require-flow-ipc-v1 docs/traces/flow-ipc-v1.ndjson
```
